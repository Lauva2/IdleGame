# 满仓恢复时序问题与候选退回

2026-10-23，d10-release01正常经营录像期间读取实际前后存档，Compare-AndroidOnline发现设施计时不一致。原始样本为NormalQA/after-annex.save和normal-motion-after.save。该段没有经济配置变更；不放宽比较容差、不将失败写为通过。

原因：Resolve先尝试地块种植，再尝试设备消耗原料。原料满仓使地块暂停时，同一时刻设备消耗腾出空间后，地块要等下一次Resolve才恢复。逐帧调用仅延后约一帧；整段离线调用可能延后到下一个事件，产生在线/离线差异。

最小复现：原料20、地块暂停，设备剩余5秒，货架剩余8秒。推进6秒后，地块本应剩19秒，旧逻辑却延迟种植。新增回归在旧代码失败，日志NormalQA/core-fullwarehouse-regression-before.txt。此项作为重要功能缺陷处理，d10-release01不继续作为最终交付候选。

修复：同一时间戳发生设备消耗后再次解析生产状态，直到没有新的设备启动；每次额外解析都启动一个正时长设备周期，额外次数由设备数量界定，不改秒数、售价、容量或解锁门槛。新增满仓多链升级状态的一小时30FPS分块与整段对照，检查全部库存、销售、生产总数及设施周期。

修复后22项核心测试通过；新的非开发候选d11-release01正在构建。旧版实际运行、异常、录像及两段5分钟性能均保留，不沿用为新候选通过。d10-release01已记录的两段统计为29.47/29.79FPS、P95均33.33ms，首段最大3010.43ms保留；不足30分钟，未完成性能验收。

美术、布局和动作源本轮没有变更，但因构建身份改变，仍须更新运行证据并由同一独立角色确认适用性。
