## 3. 历史问题复验

### ART3D02-001：主体与环境正式完成度不足

状态：**部分修复，未关闭**  
严重性：**美术阻断**

实际改善：原纯球团树冠已改为波瓣形；增加了独立叶片和侧边林木。近色错缝屋瓦、未开放货架的封布、绳与锁扣保持，不再描述为旧版棋盘屋顶或无语义方体。

当前仍有问题：

- 多个正面树冠团块出现近似开裂的深色细缝和明显放射折面，整冠有皱缩、被切开的观感。
- 叶片及凸出边缘形成较多零碎尖角，未与柔和、圆润的既定方向统一。
- 粗主干的几何分叉仍明显，表面少量竖线未充分收束连接关系。
- 侧边林木由直灰干与大而硬的薄叶组成，重复堆叠和材质差异明显，尚未形成有目的的森林空间层次。

证据：两平台 `05-region-0.png`、`16-annex-before.png`、`16b-annex-after.png`、生产 `dynamic-0000.png`；Android `23-report-120ms.png`。这些问题在实际全景尺度就可见，不是只在极端放大时出现。

这是对可见完成度的判断，不把程序几何制作方式本身列为缺陷，也不要求写实树林或无目的增加模型数量。

复验条件：正式主树在全景、纪念和安卓实际尺度下具有连贯柔和的冠体与枝干，不出现裂缝状暗线、破碎尖边或显眼拼接；周边树木与树屋、角色材质和形体语言统一，主次清楚。需提供新候选实际运行画面，下一版修复描述不能关闭本项。

## 4. 本轮新增问题

### ART3D05-001：顾客浏览路线持续重叠，遮蔽物种与购物动作

严重性：**重要**

Windows 顾客 `0018～0024` 中猫头鹰与兔子在同一段浏览位置高度重叠，正面停留时几乎合成一个角色；`0044～0052` 中小熊与兔子也发生相似遮蔽。Android 顾客 `0016、0020` 可见猫头鹰挡在兔子前，`0032` 可见小熊挡在兔子前，证明不是只在一个 Windows 截图瞬间发生。

这里记录的是持续的视觉遮蔽和路线拥挤，不从抽帧推断具体碰撞系统或移动代码原因。普通经过时的短暂遮挡可以接受，多个浏览停留阶段长期叠在同一位置则削弱“各自到店购物”的可读性。

复验条件：在实际安卓连续运行中覆盖五熟客完整循环及重复循环，浏览、购买和离开阶段都能分辨角色，避免长时间重叠成一体；检查高峰并发、正面和背面姿态，不只选取错开的好看时刻。

### ART3D05-002：离店边界衔接突兀

严重性：**一般**

右侧离开阶段，人物可继续显示在墙柱外，身体和脚局部超出楼板边缘，缺少可理解的承载或出入过渡。Windows 顾客 `0040、0060`、生产 `0070`，Android 顾客 `0016、0044、0052` 可见相关边界位置。

### ART3D05-003：安卓采集出现严重停顿，动态结论受阻

严重性：**重要，验证异常；根因未定位**

CompleteRuntime 的生产帧相隔约 9.63 秒与 59.34 秒，顾客末段也有 10.12 秒间隔；制作方同时报告录屏/导图期间严重停顿。不能用“完整导出”“完成日志”或总运行 208 秒覆盖这一事实，也不能把此异常直接宣称为正常游戏必然冻结。

证据：CompleteRuntime 两份 CSV、metadata，上级调查截图、原始录像及日志。本报告没有完整观看 MP4，因此不额外给出视频中冻结次数或持续时间。

复验条件：将截图导出与纯录屏分开，在同 APK 正常模式下复现/排除；保留输入时间、帧率/帧时间、日志和原录像，交代采集负荷与正常运行的差别。取得足够连续、正常速度的真实安卓动态后，再评动画和反馈；性能仍须按工作流另测。

本轮仍不能确认短购买手势是否完整可读、手持物与销售事件是否准确对应、转向是否跳变、足底是否滑动、各姿态是否穿插，以及连续点击与拖动是否稳定。

正常重启截图中报告可见；普通 tap 后对应截图仍停留在报告，而 120 ms 同点操作后的截图已回到主场景。这能证明部分操作最终生效，不能证明常规短点按稳定，也不能单凭截图确认未响应发生在游戏、ADB 或采集时序的哪一侧。
