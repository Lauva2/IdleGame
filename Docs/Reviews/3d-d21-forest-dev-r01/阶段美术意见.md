## 1. 阶段结论

## 3. 具体问题、R02 复验及标准

### D21-DEV-001：重要发现物的世界内遮挡

**R01 观察：需先整改的重要阶段问题。** 13-creek-wetland 中，露铃草主体被前方高树冠及观察牌覆盖，主要只露边缘；14 的发现弹层虽能辨认花草，却不能弥补点选前无法看清世界实物。03 野莓前缘与牌靠近；18 松脂树下部树疤/容器与牌挤在一起。21 旧亭正面另受树冠遮挡。

**R02 复验：默认静态构图已有明确改善。** 03 野莓红果与小容器可见，观察牌下移并分离；13 四簇露铃草的浅色花穗及蓝绿色叶片完整可见；18 松树主干、琥珀色采脂位置和根部容器可见，与观察牌有间隔；21 旧亭正面前景树冠已清开。不能保留“R02 露铃草仍几乎完全遮住”的旧描述。

**最终复验标准：** 同一新 APK 中，默认、实际可达的放大/缩小/平移和回中状态下，关键采集物轮廓及可操作状态能辨认；标记不持续挡住识别部分，实际点选实物/路径能够打开对应内容。三发现的未发现、可采、恢复中、满仓等待均需有实际状态证据。若实际 APK 仍遮住关键对象，应按工作流的不可辨认/遮挡关键操作条款处理。本次不宣布此项最终关闭。

### D21-DEV-002：旧亭修复成果的可见内容偏少

**R01/R02 共存，重要阶段意见。** 20 的文案明确写“修好长椅与茶桌，让邻居重新相聚”；22 写园丁的茶、老师放在木桌上的旧书。21 实际能看到屋顶颜色与破损修补、拦板移除及两盆花等变化，不能说修复前后毫无变化。但 R02 前景清开后，默认镜头仍主要呈现木地板和屋顶，长椅、茶桌及文案所指的生活成果不易辨认，阶段目标的视觉回报偏弱。

**复验标准：** 修复前后使用可比较的实际默认取景，并展示玩家能正常到达的近看方式；能看清已承诺的修复用途与陈设变化。若相关陈设已有而被屋顶/取景挡住，应以正常可操作视角证明可见；若没有，应处理画面与文案的落差。此意见不臆断模型是否存在，也不额外要求增加角色玩法或整段演出。最终结论以实际画面为准。

### D21-DEV-003：温室身份与培育物的视觉占比不足

**一般质量问题及补证点。** 08 四位分布、中央走道与编号清楚；15 能看出两类在培育的植物，选择面板09也能区分种苗。植株尤其初期苗相对土箱/编号牌偏小，观察时先读到大编号，再费力找植物。剖面视图有木边框和柱，温室玻璃/围护的身份较弱。本批01能见小院中未修温室的结构，但缺少修复后外观与进入剖面的可比较呈现，不能仅因剖面无顶就宣称资产缺失。

15 同时出现红果与蓝绿色植株/回执，可能包含前一轮野莓收获后尚未结束的短时表现；模拟推进的静态帧不足以认定“露铃草长出红莓”。不据这一帧判生产状态错误。

**复验标准：** 实际新 APK 中提供温室修复前后外观、进入剖面与返回、四位两种植物的生长/成熟/收获连续段；植株、编号、当前种类及待切换种类能清楚对应。满仓停产、解除满仓后恢复和本轮结束才切种类需真实演示，不能靠准备好的单帧推断。收获短回执应在正常时间消退，不长时间遮住新作物或制造错误产物印象。

### D21-DEV-004：三段林区的环境差异与精修仍偏弱

**一般质量问题。** 三段目前大量共用同色草面、相似树形和宽直石路；林缘靠野莓、溪边靠河桥、苔石靠松树/旧亭区分。湿地和苔石环境自身的地貌/植被差别较弱，文字页签承担了较多辨区工作。大块浅色清地边界明显，树木重复和地表空白仍可见。新增层叠松冠可与圆冠旧树区分，主题统一，但造型较简。

**复验标准：** 在普通默认镜头及实际平移过程中，各段的既定地貌/地标具有稳定可读的空间身份，路径与目标关系清楚；保留点选对象可见性，不能为填空再次挡住发现物。此项是完成度意见，不要求扩增已授权区域数量或玩法。

### D21-DEV-005：采莓后的引导文字不同步

**一般界面问题，R02 仍见。** 05-gather-receipt 顶部目标已经是“野莓新家·修复温室”，底部却仍提示“观察林缘的野莓苗，采集第一份森林发现”。两处指向不同阶段，首次采集完成后会继续要求已经完成的动作。02 邀请中仍说“等开张茶会结束”，在本批已准备为首章结束的入口语境中略显滞后。

**复验标准：** 实际完成首次采集后，目标、底部提示与可执行下一步相互一致；首次入口文案与真实解锁时点吻合。此项不能用实际按钮还能工作而忽略其指引问题。

### D21-DEV-006：长弹层底部尚无安卓可达证据

**证据缺口，不是已确认的安卓裁切缺陷。** R01 的04/14/19发现弹层、02邀请、部分 request-after 对话和23手记下部在离屏图中未完整显示，已知 Host 高度限制足以影响其布局。不能据此判关键按钮永久丢失，也不能把39条处理器 PASS 当作真实玩家能滚到并按下的证明。

**复验标准：** 新 APK 默认、长屏、窄屏以及模拟缺口下实际打开、滚动并点击至末尾；完整正文、种苗/修复/关闭/继续按钮、发现手记末项及许可末行需真实可达。每种画幅记录真实分辨率/密度/安全区，避免只提交拉伸同一张图。

### D21-DEV-007：三新配方及经营端接入的视觉覆盖尚不完整

**证据缺口。** 10 莓香茶配方面板的图标、原料数量、用时、价格和循环制作按钮可读；16 清露喷雾以浅蓝瓶及金色喷头可辨，20 护木香膏以绿色盖、金色盒身可辨；04/14/19 的三原料大图也彼此不同。这些图不能推导清露喷雾、护木香膏的完整配方面板、锁定/缺料/可制作状态均已检查。仓库、货架、新增商品实际持取和销售、图鉴/报告的新增行也没有在本批形成完整视觉覆盖。

**复验标准：** 同包补齐三新配方各完整面板及关键状态、新旧商品共同显示的仓库/图鉴/报告、实际制作与货架销售动态；图标及世界物体应能对应，不仅靠文字名字分辨。保留已有五体型购物与足身/手物接触表现的同包复验，新图标不能自动获得旧动作通过结论。

1. 构建输入/源码身份、APK SHA 与设备安装身份、MuMu实例/Android版本/分辨率/密度/刷新率及安全区；媒体原图/原片/原帧索引与明确准备范围。

4. 自然运行连续证据覆盖顾客行动、收获/制作/销售反馈、面板滚动与过渡，并覆盖新林区/温室动态及简化动画设置；不得以模拟推进或静态通知替代。实际平移来源出画后的反馈也应保持与真实可见来源一致。
5. 默认、长屏、窄屏及模拟缺口下，新旧长文末尾与关键按钮真实可达；不把当前 Editor Host 限制作安卓通过或失败证据。
