# 项目与C盘空间清理

2026-10-25，用户指出项目目录过大、C盘接近满盘，随后明确确认“允许删除解码帧，保留原片与索引（推荐）”。根目录AGENTS已记录保留策略修订，验收分数与其他门槛保持。

主要增长来自本任务长期累积的取证解码帧。本任务C盘目录当时约58.2GB逻辑文件、53.8GB实际分配空间；Codex会话日志另约6.1GB，仅统计大小，没有读取内容或删除聊天记录。

已清理169组、58,890个解码缓存文件及目录内元数据，元数据另备份；对应165份原始MP4在删除前后全部SHA一致。原始录像、必要原图、原始评审、存档、源码、交付APK及原始时间/SHA索引保留。历史索引中的帧路径是冻结时记录，展开帧现已按授权清理，不声称仍全部存在；复核时可从对应原片按索引时间重新导出。新导出文件如需与旧文件字节比较，还须匹配原编码器版本及压缩参数，不能只凭像素相同声称旧PNG字节SHA相同。

另外删除停止运行的Unity Library缓存、Python字节码与三份闲置Android模块解包缓存；实际安装的Android模块全部文件仍在，抽查20份SHA未变。Unity下次打开会重新生成Library。2,932份完全相同帧先共享NTFS存储，路径和字节未变；Git使用不裁剪历史/引用日志的标准打包，完整性检查通过。试压归档收益有限，三组原帧均原路径恢复、完整SHA校验后才移除试验压缩包；随后按用户授权统一清理缓存。

约释放57GiB（以Windows容量显示口径计），C盘从不足1GiB恢复到约43GiB可用，E盘约14GiB可用。详细前后值见summary.json，操作期间系统仍有少量正常写入。未可靠对应原片的15组旧资料约5.08GB逻辑文件继续保留，未据文件名猜测后删除。

201项最终游戏输入、最新APK、原始R01及61张必要原图再次核对全同SHA，本轮只整理存储，未产生新的游戏/美术候选。后续取证优先E盘，按需生成必要动态片段，及时清理可再生的完整展开帧，避免继续向C盘累积。原始资料和全部游戏延期验收限制保持。
